FAQ & Troubleshooting

Frequently Asked Questions

1. Which coding agents can use BLA?
Any coding agent that supports local MCP servers or SKILL.md instructions: Claude Code, Cursor, Codex, Gemini CLI, Windsurf, Google Antigravity, OpenCode, VS Code, and GitHub Copilot CLI.
2. Does BLA slow down my app or alter its runtime output?
No. All semantic budget breakers and tarpit meshes are guarded by O(1) number-theoretic opaque predicates (7x² - 1 ≠ y² mod 7) that evaluate in a single CPU instruction and never enter the decoy branches at runtime.
3. What happens when an attacker runs REA against a BLA-protected app?
1) REA's JS/Electron engine degrades to parse_status: "partial" and examination.status: "limited", with IPC channels unresolved (channel: null).
2) REA's Rust, Electron Fuse, Flutter/Dart, SQLite, and Safetensors/GGUF inspectors abort with deterministic capacity or column evaluation failures.
3) Feature-tracing agents get trapped in 36 Fake XRef state machines and Honey Source Maps (enclave://tee-runtime/), burning up to 2,532x more tokens.
4. Do I need Hopper, Ghidra, IDA, or WABT installed?
No. All 19 format shields are built directly into bla-shield with zero external binary dependencies.
5. How do I check readiness or update BLA? 
npx bla-agents@latest doctor
npx bla-agents@latest update
npx bla-agents@latest setup
